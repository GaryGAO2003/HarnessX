## 1. 问题:池为什么不专业化(三个原因,均有证据)

CH4 的「按子任务分工」预设池里有专才。实测没有:修复后 K=4 池的四个变体
只差 1 / 6 / 36 行提示词,V6 与 V7 的 processor **完全相同**,**没有任何变体是某类子任务的专家**。
旁证:B-1 可利用互补性 = 0;C-4 演化对五种能力的提升几乎均匀(+8.3 ~ +17.9)。

追因得到三条,全部指向**演化压力的形状**,而非分解质量
(四个失败计划已逐条读过,分解结构均正确;失败是预算与合成器编造):

| # | 症结 | 现状(证据) | 论文/应然 |
|---|---|---|---|
| **1** | **门的作用域** | `--regression-baseline` 默认 **`global`**;s1k8b103 命令行未传该旗标,lock 亦未记录(global 是字节等同默认) | §4.5 p.11 逐字:「the seesaw constraint is **scoped per-variant**: a candidate targeting variant k is **tested only against tasks routed to k**」 |
| **2** | **cluster 函数** | 代码 `cluster_source = "gaia_level"` —— 按**难度** 1/2/3 分簇 | 论文只说 "that task's cluster",**未公布构造**(M-02)。难度 ≠ 能力:两道 L2 题可能一个查文献一个算流体 |
| **3** | **诊断信号** | `failure_category` 分布 = {`gaia_level_2` 322, `gaia_level_3` 130, `gaia_level_1` 71, None 1125} —— **就是难度换名**;`implicated_components` **全跑为空(1,648 条,零)** | 循环需要能力级失败归因才能定向演化 |

**原因 1 是反专业化约束**:专才的定义就是有得有失;global 作用域下,
「擅长 A 但弱于 B」的候选必被门拒。**开关早已建好(M-23),但默认停在禁止专业化那一档。**

M-23 当时记「论文有两读、待裁」。**§4.5 p.11 那句话解决了歧义** ——
§4.1 的全局表述描述单 harness 循环(变体出现之前);多变体一旦存在,论文明说 per-variant。

**分解恰好补上 2 和 3**:子任务类型(search / browse / compute / verify)
**就是**由任务自身导出的能力标签,且逐子任务可得。

## 2. 论文给的两条外部锚

**① 变体隔离本就是为 GAIA 这类异质任务设计的**(§6.2):

> "The exception is **GAIA GPT-5.4 (∆=0.0), where task heterogeneity prevents a single harness
> from improving aggregate accuracy** — an observation that motivates the variant-isolation
> ablation in Section 6.3."

| 策略(GAIA 103 题 / GPT-5.4 / 15 轮) | Final | Peak | Final−Peak |
|---|---|---|---|
| Ensemble(K 变体) | **87.4%** | 87.4% | **0.0** |
| Global(单 harness) | 49.5% | 73.8% | −24.3 |
| **我方 s1k8b103** | **74.8%** | 80.6% | **−5.8** |

我方数值卡在两者之间,与「跑的是半残版 Ensemble」一致。

**② 论文自认没测充分的口子,正是本方案所在**(§6.3 末):

> "Finer-grained strategies (**Domain-aware clustering, Task-level tournament**) were explored at
> pilot scale (30–40 tasks, ≤8 rounds) but **lack sufficient rounds and tasks for statistically
> meaningful comparison**."

⚠️ 另注 §6.4:AEGIS 四阶段 vs 单 agent evolver,87.4 vs 86.4(**差值在 1 SE ≈ 3.3% 内**),
AEGIS 仅省 14% token ⇒ **不要指望改 meta-agent 架构提分**,增益来自隔离基础设施。

## 3. 四项新增(全部旗标化,默认关)

### A1 · 门作用域 —— **零开发,机制已验证**

`--regression-baseline per_variant`(M-23 已建,SPEC §7.19)。默认 `global` 不动。
**这是投入产出比最高的一项:一个旗标,直接检验「我们把机制关了」这个假设。**

**Aug-02 测试核验(16 条,全绿)**——`tests/test_regression_baseline.py`:
- `test_default_baseline_is_global_and_byte_identical` ⇒ **「加而不改」的纪律已被证明**
- `test_baseline_flips_the_seesaw_decision` ⇒ 旗标确实改变门判决,不是空接线
- `test_run_gate_threads_the_baseline_end_to_end` ⇒ 接线通到底
- `test_lock_records_regression_baseline_only_when_per_variant` ⇒ 非默认值才写 lock

⚠️ **但从未在真跑里用过** —— 单元级已证,live 级未证。首跑须核 lock 是否记录该旗标
(默认档不写,per_variant 才写),以此确认真的生效。

### A2 · 可插拔 cluster 函数

```
--cluster-source {gaia_level, subtask_type}     默认 gaia_level
```

- `gaia_level`:**与现行为字节等同**(现路径不动)
- `subtask_type`:cluster(x) 取自**分解计划里该子任务的 type**

**作用域限定(避免 M-13 的泄漏问题)**:仅用于**子任务级路由**。
子任务类型在该子任务执行**之前**由计划给出,天然满足「映射须解题前可得」;
任务级路由不启用此源(那需要先分解,语义另议)。

### A3 · 逐子任务信用信号 —— **本方案的关键一项**

现状:`TypeCreditLedger.record(pairs, passed)` 把**任务级**成败原样写进链上每个
(变体×类型) 格子(均值 4.30 个),**测不出是哪个变体哪一步起作用** ⇒ 分工臂在构造上测不到东西。

```
--decomp-credit {task, subtask_convergence}     默认 task
```

- `task`:**与现行为字节等同**
- `subtask_convergence`:逐子任务记信用,**成败判据 = 该子任务是否在步数上限前收敛**
  (撞顶 = 未收敛 = 失败)

**为什么用「是否撞顶」**:免费、客观、二值,不需要额外 rollout 或裁判;
且**正好对齐 C-1**(88.7% 的失败是「没做完」)。实测撞顶率 22%,信号密度足够。
**局限须写入威胁章**:它测的是「收敛性」不是「正确性」——
一个提前结束但答错的子任务会被记为成功。这是刻意的取舍(免费换粗糙),
更精确的替代(逐子任务 LLM 裁判 / 反事实换变体重跑)成本高数倍,列为 future work。

### A4 · 合成器诚实约束

```
--decomp-synth-guard {off, strict}              默认 off
```

- `off`:字节等同
- `strict`:合成器提示词追加约束 —— 任一子任务未产出所需信息时**必须显式声明**,
  **不得从参数化记忆填补**

**证据**:`20194330` 的合成输出为
`"Based on the known content from the Game Grumps episode …"` ——
上游 browse 撞顶什么都没送到,合成器用模型自身记忆编了一个自信的答案。
**这是正确性 bug,不是效果问题。**

### B · 分解方案的两项改进(同样旗标化)

- **分支计划**:放开 planner 产出非线性计划(实测 17/20 为纯线性链 ⇒ 单点失败株连全链)
- **子任务重试**:子任务失败先重试再往下走

## 4. 测试床:不用换,而且分辨率更高

分化要多分簇、功效要每簇多样本,通常打架。但**分解把评估单元从「任务」换成「子任务」**:

| | 单元数 | 分簇 | 每簇 n |
|---|---|---|---|
| 现状(任务 × 难度) | 103 | 3 | ~34 |
| **本方案(子任务 × 类型)** | **103 × 4.30 ≈ 440** | 4 | **~110** |

⇒ **分簇信号的统计分辨率约提高 3 倍,且 GAIA-103 不动,CH3 可比性不丢。**

**统计口径**:一律**同题配对**检验,不用聚合 pass@2 差值 ——
实测噪声地板 SD 4.57pp(n=103)/ 6.41pp(n=50,直测),2SD 门槛 9.1 / 12.8pp,聚合差值基本过不了线。

## 6.5 可比性:哪些能比,哪些不能(用户 Aug-02 追问)

**能比 —— 而且正是该比的**:

| 对比 | 性质 | 说明 |
|---|---|---|
| 新池 **vs 我方原版** | ✅ **单因子消融** | 同床同题同评分,只动门作用域。比任何跨论文比较都干净 |
| 论文档 vs 分化档 | ✅ 单因子消融 | `per_variant`+`gaia_level` vs `per_variant`+`subtask_type` |
| 论文档 vs 论文 Table 5 | ⚠️ 仅限**同跑内对比** | 跨模型(我方 DeepSeek V4 vs 其 GPT-5.4/Opus 4.6),绝对分不可比(M-15) |

**不能做的只有一件**:把**分化档**的数字摆进 Table 5 那一行称「我们复现 Ensemble 得 X%」。
按子任务类型演化已非其所测方法,而是 §6.3 末自认未充分评估的 domain-aware clustering。
⇒ 定位应写成「**扩展**其未测部分」,不是「复现」。

### 🔴 更大的风险:修复效应与门作用域**同向混杂**

`s1k8b103` 是**脏**的(三条投递路径全坏)。若拿「新跑(带修复 + `per_variant`)」直接对
`s1k8b103`(无修复 + `global`),则**两因子同时变**:

```
新跑 = per_variant + 产物真的送达
旧跑 = global      + 提示词/工具/processor 三路静默丢失
```

分不清分化来自「门放开」还是「产物终于送到」。而且**两者同向**
(投递 bug 本身压制分化:候选带着装不出来的 processor 去过门 → 被拒),更难拆。

**三种做法**:

| 方案 | 内容 | 成本 | 结论强度 |
|---|---|---|---|
| **干净(推荐)** | 带修复各跑一次 `global` 与 `per_variant` | 2 × 26.5h ≈ **53h** | 单因子,可直接归因 |
| 便宜 | 两臂都在 50 题床跑 | 2 × ~12h | 噪声地板 6.41pp,配对检验仍可用 |
| 最省 | 只跑 `per_variant` 单臂,与 s1k8b103 作**描述性**对照 | 26.5h | 须写明「混杂修复效应」 |

**推荐「干净」档**:53h 在 34 天档期内不贵,而且这一对本身即论文级结果 ——
**「把 §4.5 的 per-variant 作用域关掉会发生什么」,论文自己没做这个消融。**

**缓解**:**分化程度是结构量**(不同提示词数、逐簇胜率离散度),不是准确率,
**受噪声地板影响远小于准确率**。即便准确率比不出显著性,
「专才有没有涌现」这个问题照样能答。

## 7. 风险与边界(必须随结果引用)

**🔴 一旦按子任务类型演化,这不再是论文 Ensemble 的复现**,
而是它明说未充分评估的 "domain-aware clustering"。
⇒ **CH3 的复现必须用论文配置(`per_variant` + `gaia_level`)单独跑一次保住可比性**;
**不得拿新配置的结果去对论文 Table 5**。

**A3 的判据是收敛性而非正确性**(见上),须入威胁章。

**K=4 一类型一变体是设计选择**,不是论文参数(论文未给 K),须入 lock 与偏差表。
