# L0 官方基线 · 全程 SOP 审查（2026-08-14）

审查对象：`runs/L0_103x10`，R0–R15 十六轮 × 103 题 = 1648 条 rollout，任务侧 $1395.39。
证据源：`data/task_history.jsonl`（逐题逐轮）、`data/ship_outcomes.json`（官方自记的
"这次上车预计修好哪几题"）、`audit.jsonl`、87 个 meta 会话转录（3509 次工具调用）、
两个 checkout 的源码 diff。探针脚本在 scratchpad `sop_audit{,2,3,4,5}.py`。

七块：溯源保真 → 协议合规 → 测量效度 → 内部效度 → 归因效力 → 成本账 → 证据通道。
最后一节是这份审查对 GHX 的可执行结论。

## 1. 溯源与保真

`baseline` 分支 HEAD = `0b16a20 deviation(aegis): --no-early-stop`。**全程只有这一条
声明过的偏离**，跟踪文件无未提交改动。

**`harnessx/aegis/` 在两个 checkout 之间零字节差异。**元代理本体——Digester /
Planner / Evolver / Critic、六道门、ledger、`regressions.py`——不受任何 GHX 工作影响。
这是本次审查最重要的一条保真结论。

### 发现 P-1：R11 起，导入的 `harnessx` 换了一棵树（未声明偏离）

venv 里 `harnessx` 是 editable 安装，映射到**主 checkout**。于是调用方式决定导入哪一份：

| 调用 | `sys.path[0]` | `import harnessx` 解析到 |
|---|---|---|
| `-m recipe.gaia_evolver.run_meta_aegis`（手册写法） | baseline 根 | **baseline/harnessx** |
| `recipe/gaia_evolver/run_meta_aegis.py`（R11 续跑实际写法） | 脚本所在目录 | **主 checkout/harnessx** |

R11 的续跑用了脚本路径。行为指纹坐实了切换——用会话文件 mtime 跨度算每轮吞吐：

```
R0..R10   0.62M token/min  (n=11, SD 0.10)   max 0.72
R11..R15  1.00M token/min  (n= 5, SD 0.06)   min 0.89     两组零重叠，1.61x
```

原因不是算法：把行尾符归一化后，两棵树的真实差异只剩四个文件——
`core/runloop.py` 98 行、`core/processor.py` 61 行、`core/attribution.py` 15 行
（三者全是 M12 消息面录制器，recorder 未装时是 no-op），以及
`providers/openai_provider.py` 40 行 = `edf660d` 的两个传输旋钮
`HARNESSX_MIN_REQUEST_INTERVAL` / `HARNESSX_HTTP_TIMEOUT`。
**两个旋钮在两边 `.env` 里都设了**，但 baseline 那份代码不读它们。
`file_uri.py` / `step_countdown.py` / 两个 blocklist / `serper_search.py`
的"几百行差异"**全部是 CRLF，语义零差异**。

**影响判定**：语义不变（aegis 逐字节同、core 改动门控），**变的是请求节流与 HTTP 超时**，
即墙钟。分数无可测影响：R8–R10 均值 74.7，R11–R15 均值 74.6。
**但凡是引用墙钟/吞吐的结论都必须按 R11 断开。**

同类提醒：L2 臂吞吐从 R0 的 0.48M 爬到 R9 的 1.10M——旋钮是 campaign 中途落地的，
**两臂的传输节流在时间上都不是常数**。臂间墙钟不可比；成本与步数可比（R0 对照臂
配对检验已证）。

## 3. 测量效度

```
exit:  done 1409 | budget_exceeded 235 (14.3%) | error 4
```
`budget_exceeded` 的 rollout 仍有 **25/235 = 10.6%** 判通过——耗尽预算不等于失败，
凡是把 budget_exceeded 直接当失败的分析都会偏。

**题床的三段结构（16 轮逐题通过次数）：**

| 段 | 题数 | 占比 | 含义 |
|---|---|---|---|
| always 16/16 | **27** | 26.2% | 白送的地板 |
| never 0/16 | **6** | 5.8% | 真天花板 |
| flip | **70** | 68.0% | 全部分数运动发生在这里 |

分层：L1 n=39 均值 80.3%（1 题 never）、L2 n=52 均值 66.6%（5 题 never）、
L3 n=12 均值 42.7%（**0 always、0 never，整层是彩票带**）。

## 4. 内部效度：有没有真效应

Cochran's Q（103 个配对被试 × k 个处理，二值结局，正是这个设计的检验）：

| 窗口 | Q | df | p | 判定 |
|---|---|---|---|---|
| R0–R15 | 46.16 | 15 | **0.0001** | 有轮次效应 |
| R0–R7 | 21.29 | 7 | **0.0035** | 有轮次效应 |
| **R8–R15** | 8.49 | 7 | **0.291** | **测不出** |
| R13,R14（真同配置） | 0.43 | 1 | 0.520 | 测不出（应当如此） |

配以方差比（观测轮次方差 ÷ "每题各自一枚独立硬币"模型的方差）：

```
R0..R7   ratio 2.66   轮次把题目相关起来了 = 真有共同因子
R8..R15  ratio 1.06   恰好就是投币机
```

**结论：系统在 R7/R8 之前确实学到了东西，之后停了。峰后八轮的一切起伏（80→71→80→…）
是掷硬币。**这条同时解释了为什么原文 Fig.4 的 −24.3pp 崩塌没复现——这条床上峰后
既没有上升也没有下降，只有噪声。

**持久性**：对 70 道 flip 题做游程检验，平均 z = −0.342（t = −2.37），轻微"黏"于
i.i.d.；单题显著黏的有 **10 道**（随机期望 1.8）。看它们的序列，多数是一次性台阶：
`0000000000000111`、`0011111111111111`、`0111111111111111`。
**确实发生过真正的持久转化，约 10 题。**
其中 `1dcc160f` 是 `0000001110000000`——**拿到又丢掉**，任务层面的踏车受害者。

## 5. 归因效力（本次审查的核心）

官方自己在 `ship_outcomes.json` 里记了每次上车的 `predicted_tasks`。于是可以给
这条环的因果主张打分。口径：只算"上车前一轮确实失败"的预测（否则无物可修）。

```
13 次上车，点名 78 道正在失败的题，上车轮修好 33 道
```

零假设不能用边际通过率（条件在"上一轮失败"上会改变胜率：全矩阵实测
P(pass_r | fail_{r−1}) = 34.6%，而边际是 42.7%）。**用置换检验**：每次上车从
"该轮实际正在失败的题池"里盲抽同样多的飞镖，重复 20000 次。

```
盲飞镖修好 28.75 ± 3.50 题
官方环   修好 33 题
lift = +4.25 题 = +1.21 SD,  单侧 p = 0.142
```

**十六轮、$1395、13 次上车，诊断→修复通道相对盲飞镖的增益点估计为正，但达不到
统计显著。**

分桶（有效预测 / 修好 / 飞镖期望）：

| 桶 | 命中 | 飞镖基线 |
|---|---|---|
| prompt | 11/19 = **57.9%** | 45.1% |
| config+processor | 8/16 = 50.0% | 45.7% |
| config | 3/8 = 37.5% | 49.2% |
| **processor** | 8/25 = **32.0%** | 42.8% |
| tools | 1/4 = 25.0% | 17.2% |

**处理器桶是唯一明显低于随机的桶。**而处理器恰恰是图所描述的对象。

**瞄准不是问题，修复才是**：被点过名的 46 题平均通过率 46.5%，没被点名的 57 题
87.2%。诊断**准确地找到了弱题**，27 道 always 题**一次都没被误瞄**。它做不到的是修好。

修好的 33 题里有 24 题（73%）下一轮仍通过——但既然命中本身不显著，这个持久率
不能单独当作证据。

## 7. 证据通道解剖

87 个 meta 会话，**3509 次工具调用**。角色分工：Planner 622（Read 49.5%）、
Evolver 2163（Bash 47.0%、Write 18.5%）、Critic 724。

**"灭因账只写不读"在这条跑上不成立。**`df17af9` 修掉 off-by-one 之后
`regressions.md` 每轮 13–21 条实内容，被工具调用点名 **145 次**；digests 414 次、
`task_history` 188 次、`config.yaml` 309 次。指针都被打开了。

但按同一口径统计主证据：

```
派生证据（已经有人替它总结过）      主证据（真正的执行）
digests        414  11.8%          trajectories   190   5.4%
config.yaml    309   8.8%          sessions       148   4.2%
candidates     231   6.6%          _trace.jsonl     2   0.1%
task_history   188   5.4%
regressions.md 145   4.1%          任意主证据合计  327   9.3%
```

**按角色拆：Planner 18 / 622 = 2.9%。**决定"修什么"的那个角色，几乎从不打开一条
执行轨迹。

**这条环不缺证据的量，缺的是证据的结构。**它读的全是结局的摘要——哪题失败了、
哪题回归了——而不是机制：哪一次处理器调用、在第几步、吃了哪条消息、岔向了哪个分支。

## 8. 这份审查对 GHX 的结论

**G-1 · 不要再投资"选目标"。** 诊断已经准确锁定弱题（46.5% vs 87.2%），
27 道 always 题零误瞄。图的价值不在告诉 Evolver 修哪道题，而在告诉它
**在环的哪一步下刀**。任何以"更好地挑目标"为卖点的 GHX 方案，天花板已经被这条数据封死。

**G-2 · 主证据占比 9.3% 就是图通道的入口，而且它当场可测。**
角色不是不肯读主证据，是读一条轨迹的代价太高（线性转录，因果要自己脑补）。
因果锥把主证据压成一行结构化事实。**立即可做的检验：在 L2 臂上按同一口径重算
主证据调用占比与 Planner 的 2.9%。**这是 GHX 第一个不看分数就能读的硬指标。

**G-3 · 增益必须出现在峰前。** R8–R15 无轮次效应（p=0.291，方差比 1.06）。
把臂跑到 R15 买不到任何东西。**臂间比较应当加权前八轮**，收官指标改用
"达到峰值所需轮数"和"峰值高度"，而不是终值。

**G-4 · 最干净的单点演示目标：`2dfc4c37` 和 `c365c1c7`。**
16/16 `exit=done`、4–5 步、单题不到 $4，**每一次都又快又自信地答错**。
官方证据（通过/失败 + digest）在原理上分不开"停早了"和"岔错了"；
而这两类在 U 上的形状完全不同——短锥 + 可见的分支点。
**这是图通道能做、文本通道做不到的最小闭合演示。**

**G-5 · `624cbf11` 是结构性问题伪装成预算问题。** 16/16 撞 40 步墙、$59.76。
反复撞墙在 U 上是环，环是图性质。官方环只能看到"budget_exceeded"这个标量。

**G-6 · 处理器桶低于随机（32.0% vs 42.8%）是图最该赢的地方。**
Evolver 最差的桶恰好是图所描述的对象。若 GHX 只在一个桶上做出提升，
应当先做这一个，而且论文里的增益归因可以精确到桶。

**G-7 · 回滚闸的两处可改，都不需要新机制。**
(a) noop 判据改成"下一轮实际要跑的配置是否变了"（P-2）；
(b) 回滚现在是"把该轮所有 ship 一起撤"，若用锥覆盖回归题集来定位，
可以只撤该撤的那一条。R12 那次同时撤了 C-R12-01 和 C-R12-02。
**闸门阈值 5 题与实测同配置噪声包络 ±5 题同量级——灵敏度正压在噪声边缘上，
这本身就是"噪声下达整改指令"的一个实例。**

## 附：本次审查改写的既有结论

1. **"诊断→修复与随机不可分"**——第一版用边际通过率当零假设，得 lift −0.3 / z=−0.07。
   那个零假设是错的（条件在"上一轮失败"上，胜率从 42.7% 掉到 34.6%）。
   置换检验的正确结果是 **+4.25 题 / +1.21 SD / p=0.142**：点估计为正，不显著。
2. **"角色几乎不碰主证据（1/3509）"**——那是路径正则的产物（`digests/*.md` 这类
   相对路径不匹配）。统一子串口径后是 **327/3509 = 9.3%**，Planner 2.9%。
3. **"灭因账只写不读"**——在这条跑上不成立，`df17af9` 已修 off-by-one，
   `regressions.md` 被读 145 次。该结论只适用于修复之前的跑。
