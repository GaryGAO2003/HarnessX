## B. 池的结构（分化不存在）

### B-1 · 可利用互补性 = 零
交叉拟合（奇数轮选、偶数轮评）+ 200 次置换零假设，64 道充分覆盖的题：

| | |
|---|---|
| 最强单一变体 V7 | **0.656** |
| 逐题 oracle 路由 | 0.615 |
| **头寸空间** | **−0.042** |
| 置换零分布 | mean −0.041 / p95 +0.023 |
| **p** | **0.530** |

**观测值等于零分布均值 ⇒ 确认不存在，非「测不出」。**
（变体间分歧率 0.237 vs 同变体自身 0.115 —— 分歧真实，但方向单一，是强度阶梯。）

### B-2 · 强度阶梯 + 路由锁定
成对比较全部同向：V7 ≥ V6 ≥ V3/V5 ≥ V0。
**V3–V7 从未跑过任何一道 Level-1 题（n=0）** —— V0 自 R4 起固定持有全部 39 道 L1 至 R15。
唯一挑战过 L1 的 V1（n=5）**5/5 胜 V0**，随后死亡。

### B-3 · V0 全程未演化
16 轮 `config.yaml` 逐行相同（排除 `base_dir`），72 行，hash 恒为 `6e84f09c6f42`。
⇒ **V0 是一条全程存活的未演化基线**。（其他变体是否收到过 APPLY 未查。）

### B-4 · V7 = V6 + 30 行提示词
两者 config 仅差两行（`base_dir` + `template_path`）。模板文件：V6 131 行 / V7 161 行，
相似度 0.893，**added=30, removed=0**（新增块 `## Task Specification Resolution`）。
⇒ **纯加性编辑 ⇒ 变体只能是彼此的超集，分化在结构上被排除。**

### B-5 · V1 是死支
R1 出生领 21 题 → R2 抢下 L2 簇 64 题 → **R3 归零 → R5 起永久为 0**。无后代
（存活链为 V0→V2→V3→V4→V6→V7）。**全跑账面收益最大的一次 fork 落在死掉的分支上。**

### B-6 · 编辑是全局的，不挑任务类型
两次 n 足够大的 fork，improved 集按题库比例摊在全部 5 个能力族上：

⇒ **没有任何一次编辑是类型局部的。** 换簇标签不会改变这一点。

⇒ 赢者通吃的簇级路由**永远无法**只把「它擅长的部分」给新变体。

## C. 失败模式（CH4 的动机）

### C-1 · 🔴 88.7% 的失败是「没做完」，不是「做错」

| | n | 通过率 |
|---|---|---|
| 无 attempt 撞步数顶 | 864 | **93.2%** |
| 部分撞顶 | 313 | 71.9% |
| **全部撞顶** | 407 | **7.6%** |

全部 523 个失败格中，**464 (88.7%) 至少一次撞顶**；仅 59 (11.3%) 为「做完但做错」。
步数分布：**通过中位 9 步 / 失败中位 20 步（= 上限）**。
