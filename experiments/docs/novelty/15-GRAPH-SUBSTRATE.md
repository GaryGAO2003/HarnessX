## 0. 统一机制主张

**环上三个消费者（上下文组装、循环判定、reward 回填）各自需要的都是依赖结构，
但环只维护序列，导致三处各自退化成 recency 截断、连续计数、均摊拷贝；
机制是：轨迹的真实结构是一张 def-use 依赖图，序列只是它的一个投影，
三个消费者消费投影时把结构信息全部丢弃。**

设计答案不是三个 feature，而是**一个一等公民运行时结构**：
环在运行中增量维护一张显式依赖图 G，三个经典图算法在三个环位上消费同一张 G。
这如果是错的，错的假设是"三个消费者丢弃的是同一份结构信息"——
若它们各自需要的图根本不同构（见 §4 逐位假设），基座就该拆回三件。

---

## 1. 图 G 的定义（一个基座，两层）

**数据依赖层（def-use）**：
- 节点 = 步（TrajectoryStep）；细粒度锚点 = tool call / tool result / 实体。
- 实体 = 工具输入输出中可识别的对象：文件路径（Read/Write/Edit/Glob）、命令与其 cwd（Bash）、
  URL（WebFetch/WebSearch）、消息目标。写实体的步是 def，读同一实体的后步是 use，连边 def→use。
- 结构边：tool_result 经 `tool_call_id` 指回 tool_call——**这是现存代码里唯一的引用边**
  （`trajectory.py:653`），基座是把这一根线推广成整张图。

**转移投影层**：
- 把步按工具调用指纹（现 `loop_detection.py:101` 的 sha256 指纹，机制复用）做商集，
  节点 = 指纹等价类，边 = 相邻步的时序转移。是 def-use 层之上的商图，不另立数据源。

**载体**：一个 MultiHookProcessor（注册 `"*"`），图存 `state.slots`；
compaction 时不清图（对照现 `loop_detection.py:134` 清窗逻辑——图记录的是依赖事实，
不随消息窗伸缩失效；指纹窗清空的原因在图基座下消失，见 GS-B）。

## 2. 三个算法位

### GS-A · 上下文组装位：可达性驱逐序

**主张**：recency 截断导致"最近但无关"挤掉"较远但在依赖链上"，机制是驱逐序里
没有任何依赖信息；把 CompactionProcessor 的驱逐序从 recency 换成
"从当前工作前沿（最近 k 步 + 任务实体）在 G 上反向可达性排序"，
不可达的消息先被摘要/驱逐。
**错则错在**：模型下一步需要的内容大体沿显式实体引用可达。若模型大量依赖
"从未被实体引用的远处语义线索"，可达性排序会饿死它——所以设计成**驱逐排序**而非硬过滤，
排序错的代价是次优驱逐而非信息丢失。
**动的数字**：固定 token_budget 下 `exit_reason` 中 `budget_exceeded` 占比、每解一题的 token；
机制段 = "Processors assemble context"。
**先例（F2）**：RepoGraph（2410.14684，代码 def-ref 图取 ego-network 入 context）、
HippoRAG（2405.14831，实体图 PPR 定召回）。搬运后变的一步：图的对象从**外部知识/代码库**
换成**本次 run 自己的消息历史**——先例选"检索什么进来"，GS-A 选"历史里留什么不走"。
**代码落点**：`bundles/context.py:60` make_window_mgmt / CompactionProcessor 驱逐序；
memory `retrieve` 保持不动（sliding window 照常，动的是压缩侧）。

### GS-B · 循环闸门位：转移图 SCC + 进展判据

**主张**：连续游程计数导致周期≥2 的振荡循环结构性不可见（`loop_detection.py:107`
的尾部游程被任何交错步清零），机制是计数器只编码"相邻相等"这一种环形；
在转移投影层上做在线环检测（增量 SCC），非平凡 SCC 即候选循环，
再用 def-use 层做**进展判据**：SCC 内各步若仍在写出新实体，是迭代不是卡死，放行；
无新 def 的 SCC 才触发 warn/raise。
**错则错在**："卡死循环表现为指纹重复且无新实体写出"。会漏两类——
每轮写出新实体的卡死（如反复追加日志式空转），以及不写实体、纯靠模型内部推理推进的合法重复调用。
进展判据是承重假设。
**动的数字**：`loop_detected` 对周期≥2 振荡的召回（现为结构性零）、对推进型迭代的误 raise 率；
机制段 = "tool_registry.execute → 控制处理器"。
**先例（F2）**：George et al., "Unsupervised Cycle Detection in Agentic Applications"
（ICPE'26 Companion **WIP**，arXiv 2511.10650，全文已精读 2026-08-07）。**勘误**：
论文无 "ALDG" 术语、无 SCC、无任何图论环检测——结构侧是频率超阈启发式
（CDDAG 边频 P 0.05 / FP 525；CDCS 调用栈重复子串 F1 0.45），语义侧 CDSA 对
DAG 兄弟节点做余弦相似（>0.85），混合 = CDCS 候选 → CDSA 确认（F1 0.72）；
运行时只字未做，仅 future work（"We plan to integrate real-time …"）。
搬运后变的**两**步：① 离线批量分析 → 环内在线闸门；② 结构信号从频率阈换成
真图算法（SCC）+ 进展判据。C4 冲突句因此更硬：他们自己定义了 productive cycle
（"重复但有进展"）却始终不度量 progress，且自证 "frequent edge traversals alone
are not reliable indicators of cycles"（P 崩至 0.05）——GS-B 的 def-use 新写出
判据正是补这个洞；环检测的价值在于当场改变 run 的走向。
**代码落点**：`processors/control/loop_detection.py` 整体替换判定核，
警告注入/raise 动作与 compaction 感知的**动作端**保留（`:183-207` 的行为契约不变）。
**盲区补丁（08-07，16 号 Δ12）**：自认漏报"每轮写新实体的空转"以第三级窄分支补
——SCC 候选 → 进展判据 → 仅当有新写出且输出近重复时触发输出相似度确认
（George et al. CDSA 的在线窄分支搬运，成本有界）。

### GS-C · reward 回填位：终点反向切片

**主张**：`backfill_rewards`（`trajectory.py:295`）把末端标量均摊拷贝到每一步，
导致训练记录把"碰巧在场"与"因果在链"编码成同一个数，机制是回填函数不消费任何步间结构；
换成从 final_output 的产出节点在 G 上反向切片（程序切片的轨迹版）：
切片上的步得 reward，切片外为 0（或按图距 k^(−d) 衰减，对照 2605.29697 的衰减形态）。
**错则错在**：对最终输出的影响都流经**有记录的数据依赖**。改变了模型信念但无实体流的步
（失败探索导致的转向）会被判 0——结构归因对"负信息步"天然盲。
**动的数字**：`to_training_records` 的 reward 列从常数列变成有信息列
（切片内外分离）；下游吃这份数据的训练管道样本效率。机制段 = "EvaluationProcessor →
backfill → trajectory 收集"。
**先例（F2）**：GraphGPO（2605.26684，rollout 聚合状态图上按目标距离给 step 优势）、
Liu et al.（2605.29697，实体-关系图最短路 k^(−d) step reward）。搬运后变的两步：
①先例都在 **RL 训练期**、需要多 rollout 聚合或训练期建图，GS-C 在**推理期单 run 内**完成，
零额外 rollout；②图从实体/状态图换成 **tool-call def-use 图**。
**范围延展（08-07，16 号 Δ15）**：切片经共享 workspace 实体跨 spawn 边界穿进
子代理轨迹（过程间切片搬运，HRB 1990——spawn 即调用点、子轨迹即过程、workspace
实体流即摘要边），子代理步获切片信用。
**与已占坑的关系**：HL4（信用分配）已映射 Shapley/difference rewards，
且 ⑨ 已证 LOO 式反事实在本床撞 MDE——撞墙原因是反事实要靠重跑估计统计效应；
切片是**确定性结构计算**，不做统计估计，不吃 MDE。这是 GS-C 与 ⑨ 的本质分界，
也是它绕开已证死路的理由。

## 3. 融合论证：为什么是一张图，不是三个 feature

三个算法位之间存在**交叉补贴**，拆开则每个都要独立重建对方的边：

1. GS-B 的进展判据用的是 GS-C 需要的 def-use 边——没有切片层，SCC 闸门就退化回
   "重复即嫌疑"，误报杀死它（这正是现实现只敢在名称策略上永不 raise 的原因，
   `loop_detection.py:47-49`）。
2. GS-C 的切片完整性由 GS-A 的可达性保底——被判不可达而驱逐的内容如果后来出现在
   切片上，说明实体抽取漏边；两个算法互为对方的边质量探针（这是运行时自洽约束，
   不是离线校验步骤）。
3. 建图成本付一次，三处消费。且 G 本身可随 `to_training_records` 序列化——
   训练记录从"平铺步 + 常数 reward"升级为"带依赖结构的步 + 切片 reward"，
   这是 HarnessX 作为**训练轨迹采集器**这一定位下最直接的产出物增值。

**反面自查**：若实体抽取质量差到 def-use 边大面积缺失，三个位一起塌
（GS-A 乱驱逐、GS-B 误报、GS-C 切片断裂）——基座化把三个独立风险耦合成一个共同失效点。
这是本设计付出的代价，承重墙是实体抽取的召回，不是任何一个算法。
