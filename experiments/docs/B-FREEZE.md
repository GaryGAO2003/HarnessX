## 0. 一句话

冻结 s1k8b103 演化出的变体池,在其上加一层**任务分解 + 按子任务分工**,问两件事:
**池里到底有没有类型级特化(Q1)**,以及**按特化派活能不能涨分(Q2)**。

## 1. 两问结构(裁 G)

| | 问句 | 样本量 | 由谁回答 | 文献状态 |
|---|---|---|---|---|
| **Q1** | 演化池里是否存在**类型级特化**——不同变体在不同子任务类型上系统性地强弱不同? | ~400 个子任务决策 | **B1** 的 (变体 × 类型) 矩阵 | **无人报告过** |
| **Q2** | 按这种特化派活,能否在整题正确率上胜过原版? | 103 题 | **B2 − A1** | 有负结果先例 |

**为什么拆两问**:实测噪声 SD ≈ 4.6pp,103 题单种子下 Q2 大约需要 **≥9pp** 才可检出,
而先验不利。单问结构大概率产出一个没有解释力的空结果。拆开之后:

- Q1 阴性 ⇒ **解释**了 Q2 的空(池根本没分化,分工无从谈起);
- Q1 阳性 + Q2 空 ⇒ "特化存在,但按子任务粒度去利用不划算" —— **这本身是结论**;
- Q1 阳性 + Q2 阳性 ⇒ 主张成立。

三种组合都可写。**这是本冻结包最重要的设计决定。**

## 2. 臂梯(裁 F 终裁四列)

池一律 = `s1k8b103` 终池(8 变体,V0–V7)。床一律 = `webthinker_gaia_dev.json`(103 题)。
`--pass-k 2`,种子 1,`--concurrency 10`,lab 端点,`serper` 后端。
**effort 一律拉满**(见 §4.4)。

| 臂 | 是什么 | 分解 | 路由 | 池 | 角色 |
|---|---|---|---|---|---|
| **A1** | HarnessX 原版:冻结池 + 整题路由 | ❌ | 任务级 | ✅ | **基准** |
| **B0** | 单变体 + 分解,不用池 | ✅ | n/a(单变体) | ❌ | 分解本身值不值 |
| **B1** | 池 + 分解 + **轮流**派活 | ✅ | round_robin | ✅ | **仪器**(见下) |
| **B2** | 池 + 分解 + **按账本**派活 | ✅ | ledger | ✅ | 我方方法 |

### 2.1 B1 为什么是"仪器"而不是"陪跑"(裁 F)

三条理由,缺一不可:

1. **账本开跑为空**。`TypeCreditLedger()` 无预载,冷格回退整题路由 ⇒ 单跑 B2 =
   冷启动 + 在线学习的混合物,测不出方法本身。
2. **按专长派活会产生选择偏差**:强变体拿走样本,矩阵不可信。**轮流派是唯一无偏测量。**
3. **B2 − B1 是唯一能验证"账本(=我方贡献)有没有用"的对比。**

⇒ **B2 必须在 B1 之后跑,并加载 B1 的冻结账本**(`--decomp-ledger-from`,SPEC §7.21)。

### 2.2 精确命令行

> 以下为**骨架**;完整 env / 启动器沿用 S1 的 SOP v3 脱会话启动 + 增长哨兵。
> 🔴 每一条的点火都需用户明令,本文件不构成点火授权。

**A1 —— 用整题回退通道实现(无需新建代码)**

`FileDecomposer` 在 task_id 缺失时抛 `DecompUnavailable`,而任何 `DecompError` 触发
**整题回退**;回退路径**跳过合成器、不记账本**(`subtask_pipeline.py:624, 654-687`)。
故喂一个**空 JSON**(`{}`)作 oracle 源,即得"冻结池 + 任务级路由 + 无分解":

```
--decomp-eval --decomp-source file:empty_plans.json \
--decomp-pool-from runs/s1k8b103 \
--reasoning-effort high --meta-reasoning-effort high \
--pass-k 2 --concurrency 10 --run-tag b_a1
```

**为什么这样做而不是引用演化跑的轮内测量**:走同一套评测管线 ⇒ 与 B 臂同 pass-k、
同计分、同产物,是**题内配对**的干净基准。演化跑末轮的池测量是另一口径(且 effort 不同)。
**代价 = A1 的 fallback 率 by construction = 100%**,§5 的 fallback 闸门**只对 B 臂生效**。

**B0**

```
--decomp-eval --decomp-source llm \
--reasoning-effort high --meta-reasoning-effort high \
--pass-k 2 --concurrency 10 --run-tag b_b0
```
(不传 `--decomp-pool-from` ⇒ 纯 h0 单变体,见该旗 help)

**B1(仪器)**

```
--decomp-eval --decomp-source llm --decomp-routing round_robin \
--decomp-pool-from runs/s1k8b103 \
--reasoning-effort high --meta-reasoning-effort high \
--pass-k 2 --concurrency 10 --run-tag b_b1
```

**B2**

```
--decomp-eval --decomp-source llm --decomp-routing ledger \
--decomp-pool-from runs/s1k8b103 \
--decomp-ledger-from runs/b_b1 \
--decomp-ledger-min-obs 3 \
--reasoning-effort high --meta-reasoning-effort high \
--pass-k 2 --concurrency 10 --run-tag b_b2
```

**共同固定项(不得逐臂调整)**:`--decomp-max-subtasks 5`、`--decomp-verify-gate off`、
`--decomp-subtask-max-steps` 缺省(继承 `--max-steps`)、`--regression-baseline` 不适用
(eval-only 路径不进门/跷跷板)。

## 4. 判读规则

### 4.1 噪声带 —— 用我方实测,不抄论文

论文 Table 8 的 ±5% **不作为我方口径**。S1 **完跑实测**(`--metric A`,全 16 轮结算后,
n=8 个无 ship 轮的轮间差):**均值 −0.8pp,样本 SD 4.57pp,总体 SD 4.27pp,
|Δ| 均值 3.52pp / 最大 7.77pp**。

- **±1 SD ≈ ±4.6pp** —— 论文假设的 ±5% 只相当于我们环境的一个标准差;
- **±2 SD 带 = [−10.0, +8.3] pp** ⇒ **落在带内的差一律不作改进/退化声明。**

**判读**:|Δ| < 4.6pp = 噪声;4.6–9.1pp = 需统计检验支持方可声明;> 9.1pp = 可直接声明
(仍附检验)。

> 口径提醒:样本 SD(ddof=1)与总体 SD(ddof=0)在 n=8 下差 0.3pp,**引用时必须说明用的哪个**;
> 本包一律用**样本 SD**。in-flight 快照下 n 会更小(无 ship 轮尚未结算),故任何早期手算值作废。

### 4.2 统计

- **McNemar 配对检验**(题内配对,双侧),报 p 与不一致格计数 (b, c);
- **95% bootstrap CI**(10,000 次重抽,题级重抽),差值 CI 跨 0 即不声明;
- 单种子:**方差不可估**,一律声明"单种子,轮间噪声由 S1 的 n=7 估计代替",
  不得把 S1 噪声带当作 B 臂的种子间方差(口径不同,须显式写明这是代用)。

### 4.3 功效声明(必须写在结果之前,不许事后补)

103 题、单种子、噪声带 ±2SD(±9.1pp)⇒ **Q2 可检出的最小效应约 9pp ≈ 9–10 题**。
**先验不利**:文献中分解在 GAIA 上多为负结果。**因此本设计预注册接受阴性结果**,
并以 Q1 作为主科学产出。任何"Q2 为空即失败"的读法不成立。

### 4.4 effort 口径(裁 E)

RQ2 的全部四臂 **effort 拉满且相同**(`--reasoning-effort high` +
`--meta-reasoning-effort high`)。理由:effort 是与本研究问题正交的混淆变量,
唯一正确处理是**恒定**。⚠️ 这使 B 臂与 s1k8b103(默认 effort)**不可直接比**,
故 A1 必须重测,不得引用演化跑的数字充当基准。

### 4.5 组件混淆控制

`B0 − A1` / `B1 − B0` / `B2 − B1` 三个差**逐组件分离**,禁止把总差归给单一组件。
(外部教训:2606.29914 MemDelta 指出组件混淆;2606.15017 指出 token-matched 下增益消失。
我方不配平,故成本归一读数是唯一替代防线,见 §6。)

|---|---|---|

| **Serper 实耗** | 记录并外推 | 见 §5.1 |
| **人工审阅表** | 落文件,逐题可读 | 无表不算通过 |

冒烟臂 = B1 配置(轮流派活最能暴露管线问题),`--run-tag b_smoke`,10 题子集
(从 103 床按 L1/L2/L3 配比抽,**抽样规则写死在冒烟脚本里**,不得跑后改)。

### 5.1 Serper 预算(冒烟的第二个任务:校准)

演化跑经验值 ≈ **10 次 serper / attempt**(~2,100 次/轮 ÷ ~206 attempt)。
但 B 臂每题分解成 3–5 个子任务、每个子任务一次 rollout ⇒ **每题的检索次数可能显著更高**,
**外推不可靠**。因此:**冒烟必须记录实际 serper 消耗**,按 10 题实测 × 10.3 外推单臂,
再 × 臂数,与余额比对后方可点火。**未完成此校准不得发 B 臂。**
