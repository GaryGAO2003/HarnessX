# fork 轮 candidate_reuse 计分失真与修正

> 2026-08-03。零 API 成本，纯重分析。脚本：`experiments/analysis/novelty/f_fork_reuse_correction.py`
> 复现：`python experiments/analysis/novelty/f_fork_reuse_correction.py s1k8b103`

## 0. 一句话

**每个 fork 轮，新生变体那一块的 pass@2 都是 100%——按构造必然**，因为 fork 的任务集 T_k 的定义就是"候选改进了的那些题"，而 `candidate_reuse` 的分**恰恰就是当初判定它们改进了的那次测量**。这是循环计分，它抬高了 fork 轮的报表分。

**修正后，旗舰跑 s1k8b103 的 `peak − final` 从 +5.83pp 变成 0.0000pp，且峰值落在最后一轮 R15。**

## 1. 缺陷

```
fork 条件：候选在 T_k 上"改进了、且不回退"
     ↓
T_k 被定义为"通过了的那些题"
     ↓
新生变体在诞生轮的分数 = 复用那次测量  ⇒  100% 保送
     ↓
该轮报表 pass@2 被抬高，抬高幅度 ∝ T_k / 床大小
```

## 3. 后果

### ① RISK F14 要改写，而且是**变强**

旧说法："按论文自己的噪声尺（±8.5%），我方漂移落在带内 ⇒ 复现了论文头号稳定性结论峰=终。"

新说法：**在无偏计分下，s1k8b103 的 `peak = final = 0.7476`，峰值恰在最后一轮 R15，`peak − final` 精确为 0。** 这不是"落在噪声带内"，是**逐字复现了论文 Ensemble 的签名形态**——论文 §6.3 的三条预言：*非退化轨迹（peak = final）*、*更晚的峰（R14 vs R4）*。我方峰在 R15/15。

### ② N-01（冠军保留）对本跑彻底归零

`peak − final = 0` ⇒ **冠军策略能挽回的量恰好是 0**。N-01 作为"改进项"到此为止，只保留其方法学论点（peak−final 的零假设该怎么算）。
连带作废：`04-PROBE-RESULTS.md` 探针 1 里 s1k8b103 的 `peak−final = +5.8pp`。

### ③ `pool_report.curve` 不得直接引用

任何用到逐轮曲线的地方（论文图、增益计算、稳定性论证）都必须改用 imputed 曲线，或**同时报 reported 与 imputed 并说明差异**。

### ④ 可能是论文级的效度威胁

论文 §4.5 的 fork 条件就是"改进一部分而不回退"，且它逐轮报 accuracy。**论文未说明新生变体在诞生轮如何计分**。若它同样复用候选评测，其 Ensemble 曲线有同一问题——又一处规格留白。写作时可作为 threats 提出，但**不可断言论文确实如此**（未核）。

## 5. 插补法的效度边界

- imputed 用的是**下一轮同 task_id 的 fresh 结果**。前提：新生变体在下一轮被重新实测，且期间未被编辑（非目标变体不会被改）。
- 它回答的是**"若当时做一次无偏的新鲜测量，会得到什么"**——这正是我们要的反事实。
- 但它仍带**一轮的时间差**与本床固有的重测噪声（同配置重测 SD ≈ 4.6pp）。⇒ **imputed 曲线的单轮值不应作精确值引用，只用于峰/终这类形态判断。**
- 不可插补的单元（s1k8b103 仅 4 个）按 fresh 部分处理，已在表中标出。

## 6. 建议的上报口径（今后一律照此）

1. 主曲线用 **imputed**；
2. 同时给出每轮的 **reuse_n**，让读者看得见修正来自哪里；
3. fork 轮的报表分**永远标注**其中的保送块大小；
4. 任何"peak"相关论断（含 `drift_from_peak`）一律基于 imputed；
5. 若日后改为"新生变体诞生轮重新采样"，须记 M-xx，并说明它增加的 rollout 成本 = 每次 fork 多跑 |T_k| 道题。
